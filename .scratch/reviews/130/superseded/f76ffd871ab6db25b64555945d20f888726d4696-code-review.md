## Spec

**Verdict: pass.** Every line of issue #130 is satisfied, with no behaviour creep
beyond the shared picker path:

- **Fold alef (ا/أ/إ/آ) and ya/alef-maqsura (ي/ى)** — `nameVariantKey` =
  `foldArabicVariants(name)[1]`; the three required pairs are pinned in unit
  tests, and «على علي»/«علي علي» additionally at component and E2E level.
- **Reuse, not re-invention** — the #165 fold is reused unchanged; the design doc
  states which half was reused, why the article-preserving half (not
  `foldArabic`), and that no other caller changes.
- **Warning, not a hard block** — `needsChoice` keeps the strict key; the save
  button stays enabled with the warning visible; the owner's spelling is what
  gets created (component and E2E both assert it).
- **Arabic copy via i18n, no API display text** — `partyDuplicateName` /
  `partyDuplicateNameNoPhone`; `apps/api` has zero diff.
- **Storage unchanged** — no store, schema or `createParty` diff.
- **Two genuinely different names do not warn** — six negative controls at unit
  level (real letter, superstring, word order, article, non-alef), one at
  component level and one in the E2E.

Disclosed boundaries (not regressions, and deliberate):

1. The warning renders **inside the inline create panel**, so a variant name
   submitted as typed-only without opening the panel still creates a second
   debtor silently. Folding the hard `needsChoice` gate instead would make it the
   block the issue forbids; a typed-only nudge is new UI beyond #130's scope.
2. **Suppliers inherit** the warning through the shared `duplicateNameParty`
   (same debtor-splitting risk) — documented as a non-goal in the design doc.
3. The copy now reads «باسم مشابه» for exact-spelling duplicates too, which is
   the honest wording once folded matches are possible.
4. The `/customers` create form has no duplicate-name warning at all
   (pre-existing), and a warning mounted inside a `role="status"` region may not
   be announced by every screen reader (pre-existing markup).
