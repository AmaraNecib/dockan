### Detail

- **Finding 1 — `schema-version.test.ts:136`.** Asserts `CURRENT_SCHEMA_VERSION >= 2`,
  then seeds `PRAGMA user_version = 2` and asserts `assertSchemaVersionSupported(handle, 1)`
  throws `UnsupportedSchemaVersionError` while the current build returns `2`. Without the
  bump the constant is `1`, so the first assertion fails immediately (and the gate still
  treats v2 as "newer"). Exercised the real gate + constant, not a mock. PASS.

- **Finding 2 — `supplier-account-zero.test.ts:76`.** Boots the app, creates a supplier +
  item, then `invoicesCreate` a 3×0 PURCHASE. Asserts `totalAmount=0`, `remainingAmount=0`,
  `stockOnHand=3`, and `account.balance=0` with `entries.length=0`. Without
  `supplierChargeEntryAmount` the router inserts a `PURCHASE` entry with `amount=0`, which
  the DDL `CHECK (amount > 0)` rejects, rolling the whole transaction back — so
  `invoicesCreate` would reject and the test fails. This is the strongest test in the round:
  a full wire path, no mocking of the store/router seam. PASS.

- **Finding 3 — `supplier-return-panel.test.tsx:132` ("rejects a fractional quantity instead
  of silently dropping it")** renders the real `SupplierReturnPanel` and asserts the
  `supplier-return-draft-error` alert appears and confirm is disabled. Without the fix the
  old code filtered `Number("1.5")` out and there is no draft-error element → fails. The
  helper file `supplier-return-draft.test.ts` is helper-only but is not the sole evidence;
  the panel test supplies the wiring. PASS.

- **Finding 4 — `supplier-pay-panel.test.tsx`.** Fixture: balance 800, one 1000-remaining
  invoice, amount 900 → asserts the preview line contains `900` and no
  `supplier-pay-credit`. `owed = max(0, balance) = 800`; the old
  `distributePayment(invoices, Math.min(900, 800))` applied only 800 (cap at remaining in
  `party-settle.ts:52`), so the line would read 800 and a 100 credit line would render —
  both assertions fail. Second case (amount 1200 → line 1000, credit 200) likewise fails
  under the old `min(amount, owed)=800`. PASS.

- **Finding 5 — `supplier-return-print.test.tsx:92`.** Renders the real voucher page and
  asserts the unit cell contains `—` and not the line's `unitCost: 999`. Without the fix it
  renders `<Amount value={999} />` → both assertions fail. PASS.

- **Finding 6 — `supplier-account-store.test.ts:148`** asserts `history[0].supplierName ===
  "مورد مرتجع"` (proves the `LEFT JOIN suppliers` + `toSupplierReturn` mapping); without the
  join the field is `undefined` → fails. `supplier-return-print.test.tsx:87` asserts the
  voucher renders the name; without the display the testid element is absent → fails. PASS
  **with a gap (see Note A)**.

- **Finding 7 — `activity.test.tsx:34-36`.** Three new cases; the loop asserts
  `rendered).not.toContain(tag)` and that the data tokens survive. Without the `activity.tsx`
  branches `activitySummaryText` returns the raw summary, so `SUPPLIER_PAYMENT` /
  `SUPPLIER_RETURN` / `SUPPLIER_REFUND` leak and the `not.toContain(tag)` assertion fails.
  It calls the exact exported function the page renders, so it is wired-equivalent (it does
  not mount the page, which is acceptable here). PASS.

- **Finding 8 — `supplier-return-panel.test.tsx:120` ("enables submit for a valid quantity on
  a free line (zero return value)").** Fixture invoice is all free (`unitPrice: 0`), so
  `invoiceValue = qty × 0 = 0`. The old confirm gate was `disabled = value <= 0` → the
  button is disabled for every quantity; the new gate uses `invoiceReady` (parsed lines), so
  it enables. Without the fix the assertion `disabled === false` fails. The sibling
  `:145` "submits exactly the selected line…" additionally proves the free-line path submits
  on quantity. PASS.

No finding lacks a regression test. All 8 have at least one test that fails without its fix.

## Helper-only vs wired

- Only `supplier-return-draft.test.ts` is helper-only, and it is redundant cover for finding 3
  because `supplier-return-panel.test.tsx` exercises the same helpers through the rendered
  form. No finding relies solely on a helper.
- `activity.test.tsx` tests `activitySummaryText` directly rather than mounting the activity
  page; this is the same exported function the page calls, so the branch that owns the tag
  suppression is covered.
