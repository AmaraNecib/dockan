### 1 — Major — `apps/api/src/rpc/router.ts:698`
**The repeat window is unpinned where it is applied.** The chain is pinned in three places and broken in the fourth:

| piece | pinned? | where |
|---|---|---|
| `REPEAT_WINDOW_MS = 10_000` | ✅ | `stock-adjustment.test.ts:106-108` |
| `repeatCutoff(now)` = now − 10 s | ✅ | `stock-adjustment.test.ts:111-115` |
| the store's `gt(createdAt, cutoff)` | ✅ | `stock-ledger-store.test.ts:126-155` |
| **the router passing that cutoff** | ❌ | `router.ts:698` |

**Triggering input:** change one line — `repeatCutoff()` → `repeatCutoff(new Date(0))`, or widen `REPEAT_WINDOW_MS` to 30 minutes. Every test in the branch stays green: the pure test pins the *constant*, the store test calls the store *directly* with its own cutoff, and the router tests all post inside the window. Meanwhile the owner who means it twice is refused forever — the design doc's **first** Risks row (`.scratch/implementation/295-design.md`), and the whole reason the window is 10 s and not 30 s.

**Fix — the seam already exists.** `RpcDeps.now?: () => Date` is declared at `router.ts:64-65` and already used at `router.ts:2146` (`localDate(deps.now?.() ?? new Date())`). The guard ignores it:

```ts
// router.ts:698
const recent = await tx.listStockMovementsSince(item.id, repeatCutoff(deps.now?.() ?? new Date()));
```

Then one router test: build a second router with `now: () => clock` (clock starts at the real `new Date()` — the store stamps `created_at` from the wall clock, `drizzle-store.ts:89`, so the fake clock must start real and then advance), post the same adjustment, advance the clock 11 s, post it again → expect **two** movements and `stockOnHand === 10`.

### 4 — Minor — `apps/api/src/lib/stock-adjustment.ts:126-134` vs `apps/api/src/rpc/router.ts:2085-2097`
**The identity has no `ref`, so a system row can be refused as a user's duplicate.** `matchesAdjustment` compares item, kind, delta, cost and reason — but not `ref`. Several non-user rows are `kind: "MANUAL_ADJUSTMENT"` with a **free-text** reason:

- `router.ts:2085-2097` — a purchase correction posts `kind: "MANUAL_ADJUSTMENT"`, `delta: -effectiveOriginal`, `reason` = the operator's own text, `ref: <invoice id>`.
- `router.ts:1005-1010` — a supplier return: `delta: -line.quantity`, `reason: "SUPPLIER_RETURN"`.
- `router.ts:1929-1936` — a scrap row: `reason: "<token> #<line id>"`.
- `router.ts:566-573` — the opening row: `reason: "opening"`, `delta: <initial stock>`, `unitCost: <costPrice>`.

**Triggering input:** the owner corrects a purchase with the reason `تسوية` and, inside 10 s, posts `stockAddManual({ delta: -5, reason: "تسوية" })` for the same item. The correction row and the user row have the same item, kind, delta and reason → the user row is **refused** with `STOCK_ADJUSTMENT_DUPLICATE`, although it is a different action. (The opening row is the narrowest: it needs the reason literally `opening` and the same delta.)

**Fix:** a user adjustment always has `ref: null` — put `ref` in the identity, or skip rows whose `ref` is not null. One test: correct a purchase with reason `X`, then post the same adjustment → accepted, two movements.

### 5 — Minor — `apps/api/src/store/drizzle-store.ts:1617`
**The window's boundary second is unpinned.** `gt(stockMovements.createdAt, recordedAfter)` is **strict**, and `created_at` is a one-second-resolution TEXT stamp (`drizzle-store.ts:89`, `localDateTime()`). So a movement recorded *in* the cutoff second falls out: the effective window is 9–10 s, not 10 s. The store test (`stock-ledger-store.test.ts:139-153`) reads with `repeatCutoff(now)` and `repeatCutoff(now + 11_000)` — it never touches the boundary.

**Fix:** read with a cutoff equal to the row's own `created_at` → 0 rows; one second earlier → 1 row. That documents the edge instead of leaving it to arithmetic.

### 6 — Minor — `tests/e2e/client-freshness.spec.ts:125,169`
**`__visibleFlips` can never increment, so its assertion is a tautology.** The listener reads `document.visibilityState` at event time (line 125), and line 133 patches that getter to always return `"hidden"`. Every `visibilitychange` therefore reads `"hidden"`, the counter stays 0, and `expect(readerEvents.visibleFlips).toBe(0)` (line 169) can never fail — yet the spec's comment calls it "the counter that matters".

This is not a defect in the proof: the patched getter is *stronger* than the counter. `focusManager.isFocused()` now returns false for the reader, so TanStack's `visibilitychange` listener (`focusManager.js:11-21`) fires `onFocus()` → `isFocused() === false` → the `QueryClient`'s focus handler refetches only `if (focused)` (`queryClient.js:36-40`), so no focus refetch is even possible. The isolation rests entirely on the getter.

**Fix:** count the raw events instead of the visibility state (`counter.__visibleFlips += 1` on every event, and record the state separately), or drop the counter and say in the comment *why* the patched getter is the proof. The `focusEvents` counter is real but narrow: it is installed after `goto()`, so it only counts focus events that arrive later.

The missing `x-vault-session` header is **not** a live break — the shared suite runs with `DOKAN_VAULT: "disabled"` (`playwright.config.ts:57`) and only `vault.spec.ts` runs the encrypted mode — so this is a shared-helper cleanup, not a bug.)*

## Checked and found sound

- **The e2e proves the background flag**, verified against the installed `@tanstack/query-core@5.101.4`: `focusManager.isFocused()` → `globalThis.document?.visibilityState !== "hidden"` (`focusManager.js:55-59`), `#focused` is never assigned a boolean by TanStack itself, and the interval gate is `this.options.refetchIntervalInBackground || focusManager.isFocused()` (`queryObserver.js:215`). With the getter patched, the flag is the only surviving trigger. `retryer.js:42`'s `canContinue()` has the same `isFocused()` dependency, and since `canStart()` is true while the network is up, no fetch parks in the paused state on a hidden reader.
- **The reader's numbers really are the ones that move.** The dashboard renders one `dashboardSummary` aggregate carrying both `salesCount` and `lowStockItems` (`dashboard.tsx:196-211, 296-306`), so the sales count and the low-stock row arrive in the same fetch; the row renders `{stockOnHand} / {lowStockThreshold}` (`dashboard.tsx:302-304`), which is the spec's `"5 / 5"`. `i18n.ts:183` gives `dashboardSalesCount: "عدد فواتير البيع"`, matching the spec's regex exactly.
- **Playwright's default launch args disable background timer throttling**, so a background reader's 5 s interval is not throttled to a minute.
- **The identity's arithmetic is right, and I traced every branch against the seam**: `recordStockMovements` derives an inflow's cost as `spec.unitCost ?? cache.costPrice` and stores `reason: spec.reason ?? null` (`stock-posting.ts:144-161`) — the same `item.costPrice` the guard compares against, so `expressUnitCost` dropping a cost that equals the derived one is exact. `delta` is a non-zero **integer** capped at ±1 000 000 (`packages/contracts/src/core.ts:1401`), so no rounding can make a repeat miss. `reason` is trimmed by the contract (`:1403`) and the trimmed value is what both the identity and the seam see, so a whitespace-only reason cannot split them. The web sends `reason: undefined` for blank (`stock.tsx:113`) → `null` on both sides.
- **The refusal writes nothing** — the throw is inside `withTransactionImmediate`, and the router tests assert both the movement count and `stockOnHand` afterwards.
- **The concurrency test is real** (`router.test.ts:592-616`): two `Promise.allSettled` posts, one fulfilled, one `CONFLICT`, one movement, `stockOnHand === 5`.
- **The derived-cost rule is falsifiable**: with `expressUnitCost` reverted to always compare the cost, "refuses a no-cost repeat after the item's average moved" fails (incoming 200 vs recorded 100/300) — the test is not tautological.
- **The store's `itemId` predicate is now covered** by two items in one read (`stock-ledger-store.test.ts:126-155`) — deleting `eq(stockMovements.itemId, itemId)` fails that test.
- **The new `StorePort` method breaks no implementer**: every test double spreads `...store` (`router.test.ts:853, 2680, 2740, 2797, 3438, 3786, 4720`; `backups.test.ts:245`), and the vault store wraps the same drizzle store.
- **The i18n copy needs no new test** — `apps/web/src/lib/i18n.test.ts:206-255` already sweeps the real router source for `message: "CODE"` literals and asserts each resolves to real Arabic copy; it picks up `STOCK_ADJUSTMENT_DUPLICATE` automatically.
- **The web's refusal is proven end to end at the UI level** — `items.test.tsx:1046-1057` asserts the owner sees `لم يُطبَّق مرتين` and never the raw code.
- **The e2e selection map is wired correctly** — `client-freshness.spec.ts` is listed under the catalog+stock feature and under the dashboard rule (`tests/e2e-selection.map.json:107, 236`).
- **AC4 holds**: no new port, no new package, nothing under `packages/contracts/**` touched. The diff is 25 files, of which 6 are `.scratch/` evidence.
