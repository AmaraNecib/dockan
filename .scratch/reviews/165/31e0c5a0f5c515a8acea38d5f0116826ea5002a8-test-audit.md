## Round-1 findings and resolutions

| Finding | Risk | Resolution |
| --- | --- | --- |
| Fuzzy matched related names `محمود`/`محمد` and `كراسي`/`كرسي` (both exactly 0.8) | RED | Fallback now requires a score **strictly above** 0.8 in both call sites; negative tests added in `catalog-search.test.ts` and `party-match.test.ts` |
| Catalog fuzzy ran beside strict hits (asymmetric with `filterParties`) | RED | Fuzzy is gated by `scored.length < limit`, ranks after all strict tiers (`FUZZY_RANK = max(tierRank)+1`), and skips `matchedIds`; ordering + limit-full tests added |
| Article strip shrank `الي`→`ي` (near-everything match) | ORANGE | Article dropped only when a ≥2-letter stem survives (`DEFINITE_ARTICLE.length + MIN_ARTICLE_STEM`); tests pin `الي`/`الا`/`ال` intact |
| Hyphenated stored name not matched by a space query | ORANGE | Punctuation/separators fold to word breaks; tests in both api and web |
| e2e positive-only | ORANGE | Negative controls added (`not.toContainText(unrelatedItem)`, `party-row` `toHaveCount(0)`) plus a typo-fallback assertion |
| No catalog zero-strict fuzzy test | YELLOW | Added (`falls back to an edit-distance hit when the strict pass finds nothing`) |
| Dead subsequence branch | Standard blocker | Removed; normalized edit distance subsumes the deletion/subsequence case |

## Remaining notes (accepted / deferred, no blocker)

- **Arabic-Indic digits** are not folded in name/category search (`foldArabic("زيت ٦٠")` stays `"زيت ٦٠"`). Existing phone matching already folds them via `foldArabicDigits`; name search does not. Not required by #165 — deferred.
- **`الله` → `له`** is an accepted, pinned search-only over-fold; identity is untouched.
- **Substring semantics** (`زيت` matches `زيتون`; word order is fixed) are inherited from the pre-existing `.includes()` behaviour, not new to #165.
- **e2e typo step** is positive-only (the negative control guards the article query). Covered at unit level; e2e negative is a nice-to-have.
