# Persistence behind a port, sqlite first

Persistence is reached through one `StorePort` interface; a sqlite adapter (drizzle + bun:sqlite) implements it today, and a postgres adapter is planned behind a config switch (`DOKAN_DB_DRIVER`). Procedures and use cases depend only on the port, so swapping the database changes configuration, not callers. Decided at the user's explicit request, after the tuari repo's storage layer showed how coupling to one driver spreads. Status: accepted; the sqlite adapter is the first implementation, postgres is the planned second. the port becomes real the day the second adapter lands.
