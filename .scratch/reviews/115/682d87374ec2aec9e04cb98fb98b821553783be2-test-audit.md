## Round 1 findings and disposition

1. **Two-key clear can half-apply with no per-flag signal.** Fixed: added
   `surfaces a half-applied clear instead of reading it as success` (fails only
   the `dismissed` clear by key, asserts `completed="false"`, `dismissed="true"`
   unchanged, `role="alert"`, toggle stays off).
2. **Complete shop re-records the milestone.** Accepted by design
   (`115-design.md` §1): clearing `completed` on a genuinely-complete shop is
   re-recorded from real records; there is nothing left to teach.
3. **Paired-write race (off while on-writes in flight).** Deferred — no
   optimistic coordination layer for a loopback write; the failure path is
   surfaced and retry converges.
4. **A throwing write-settled listener skipped the rest.** Fixed:
   `notifyPreferenceWriteSettled` isolates each observer (it runs in a promise
   `finally`, where a throw would be an unhandled rejection).
5. **Read-error retry.** Accepted: the shared preferences query refetches on
   mount/focus; the copy says so.
6. **Loading flicker.** Accepted, cosmetic (settings waits on `settingsGet`).
7. **Non-`"false"` values untested at the server boundary.** Fixed: router test
   refuses `"yes"`, `"0"`, `"False"`, `""`, and asserts the stored value is
   unchanged after the refusals.
8. **Deadlock sentinel budget.** Fixed: raised to 15 s and the timer is cleared
   in `finally`; `itHeavy` gives the file a 120 s budget so the sentinel can
   still fire (a real deadlock reports the sentinel, not a file timeout).
9. **E2E order dependency.** Accepted: the spec documents the shared-DB order,
   `beforeAll` resets records per `--repeat-each` group, and the completion test
   runs after.
