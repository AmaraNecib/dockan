## Spec

**Finding 1 — writes can reorder.** **Met.** The per-key tail serialises
writes; only the newest queued write reconciles. The new test holds the first
write until after the second is queued and asserts the final stored and visible
value is the last choice.

**Finding 2 — a failed write drops the cached preferences.** **Met.** The
unconfirmed value is a local overlay, never a partial `setQueryData`; on
failure the overlay is cleared and the query invalidated. The test combines a
held initial read with a failed write and asserts the sibling survives and the
rejected key is not claimed.

**Finding 3 — other tabs leave preferences stale.** **Met.** `staleTime` is
30s and the query refetches on window focus/visibility and reconnect; a
focusManager test picks up an externally written value.

**Finding 4 — failed milestone writes do not persist.** **Met.** New
`onboardingComplete` re-checks the four records and upserts idempotently
(now `store.recordOnboardingCompletion`, tested for the incomplete and complete
cases); the dashboard calls it when it observes completion, retries on each
later progress observation while the milestone is unset, and never claims a
persisted state the server rejected. A failed dismissal reverts the overlay so
the panel returns.

**Finding 5 — an existing saved sidebar choice is lost.** **Met.**
`migrateLegacySidebarCollapsed` imports `dokan.sidebar.collapsed` once when the
server has no sidebar value, then clears it; read/write failures keep it for the
next launch; a throwing `localStorage` is caught; a pending user write is never
overtaken. Five tests cover it.

**Notes**

- Clearing the legacy key when the server already has a value is beyond the
  literal ask. **Defended:** it is one-time cleanup of a stale key, and the
  server value still wins.
- Retry tuning (3 attempts, 50/100 ms) and `refetchOnReconnect` are in spirit,
  not verbatim.
- Because the overlay is per-hook, two hooks on the same key do not see each
  other's unconfirmed writes until the server echo folds in. **Accepted:** a
  direct consequence of the no-partial-cache fix; the app has one hook per key.
