## Spec

All six PR #105 findings are genuinely closed and no scope creep was introduced:

1. **Money — stock prefill.** `{itemId, cost}` guard refreshes an untouched
   value when the known cost changes and never overwrites a typed value; ref
   resets after a movement so the next refetch re-prefills the new average cost.
2. **Blocker — zero-price edit.** Edit allows a non-negative integer selling
   price and rejects blank/negative, so an item created with selling 0 by the
   sale quick-add stays editable.
3. **Money — whitespace cost.** All numeric fields are trimmed first;
   whitespace-only unit cost is `undefined`, so the api (`router.ts:447`,
   `input.unitCost ?? item.costPrice`) falls back to the known cost.
4. **Overflow.** The table is wrapped in `overflow-x-auto`.
5. **Pending row.** Other rows' edit controls are disabled while a save is
   pending; success clears only the matching draft.
6. **Keyboard.** Enter in any edit input submits.

UI-only constraint held: the diff touches only `apps/web`, `tests/e2e`, and
`.scratch`; `apps/api` and `packages/contracts` are untouched. No hardcoded
Arabic (all copy via `i18n.ts`); money/stock calculation unchanged; the
signed-delta two-step path is intact.

Non-blocking: create still requires selling > 0 while edit allows 0 (per design;
asymmetric, means an items-tab create cannot make a zero-price item); the
"untouched" prefill check compares the prefilled string, so retyping the same
value is indistinguishable from untouched.
