# Domain docs

Read these sources when exploring or changing the domain:

- Read the root `CONTEXT.md` for product terms.
- Read ADRs in `docs/adr/` that concern the area you are changing.
- Use terms as defined in `CONTEXT.md`. If a needed term is missing, note the gap for domain modeling.
- If a change conflicts with an ADR, name the ADR and explain why it may need to change.
- If a source is absent, continue without treating its absence as a problem.

This repository uses one root `CONTEXT.md` and one `docs/adr/` directory. The app packages are technical boundaries, not separate domain contexts.
