## Spec

**Finding 1 — preferences survive a packaged restart**
- **Correct.** Separate `preferences` table (not `settings`), `StorePort`
  get/set, one cheap scan + upsert, session-guarded procedures, web hook with
  the throwing-storage guard, and both state modules migrated with their seams
  kept. The store test proves persistence by closing and reopening the same DB
  file. Keys are namespaced `ui.*`.
- Note: the imperative seams now have only test callers (see Standards).

**Finding 2 — stop polling once the panel cannot render**
- **Correct.** `enabled: !hidden && !preferencesPending`; the disabled query
  never fetches, asserted with `progressFetchCount === 0` for dismissed,
  completed, and preferences-pending states.

**Finding 3 — loading shifts the layout**
- **Correct.** Skeleton header (`h-6` + `mt-1 h-5`) and rows (`p-4`, 20px icon,
  two `h-5` lines with `mt-0.5`) mirror the loaded panel's 80px/74px metrics;
  the new E2E measures both and asserts a ≤1px difference.

**Finding 4 — the fresh-install E2E owns its state**
- **Correct.** `beforeAll` resets shop records via `reset-e2e-records.mjs`
  (Playwright runs it once per repeat group); `beforeEach` clears preferences
  so server-side dismissal/completion cannot leak between tests. Auth, store
  settings, and number sequences are intentionally preserved. Verified:
  `--repeat-each=2` → 10/10, full suite 30/30.
- Note: the record reset deletes a broader table set than the checklist reads.
  **Defended:** it makes the "fresh install" state genuine rather than partial.
