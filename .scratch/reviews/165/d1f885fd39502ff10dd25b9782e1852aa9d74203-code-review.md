## Standards

**Verdict: pass, no blockers.**

- **ADR-0007 separation holds.** `packages/contracts/src/core.ts` (`normalizeTextKey`) is not in the diff. `foldArabic` is a new, separately exported search-only key documented "NOT an identity key"; `party-match.ts` keeps `normalizeTextKey` for `duplicateNameParty` / `needsChoice`, and the guard test pins `normalizeTextKey("أحمد") !== normalizeTextKey("احمد")`.
- **No dead code.** The round-1 finding (a subsequence branch provably equal to the normalized edit-distance score) was removed; `fuzzySearchScore` is one Levenshtein metric over the whole folded text and each word. `matchedIds` and `FUZZY_RANK` are live.
- **Rank ordering is derivable.** `FUZZY_RANK = Math.max(...Object.values(tierRank)) + 1`, so a future strict tier cannot let a fuzzy hit interleave.
- **Judgement notes (not violations).**
  - `foldArabic` repeats the invisible-text / tatweel-harakat ranges from `normalizeTextKey`. Sharing a range constant would DRY it, but delegating the fold to the identity key would couple the two (ADR-0007 drift). Documented in the design; left as-is.
  - The fuzzy tail (score filter → sort by score desc → `localeCompare("ar")`) appears in `catalog-search.ts` and `party-match.ts`; their pre-conditions differ (limit top-up vs empty-only), so a shared helper would need that distinction. Accepted as a second occurrence.
  - `ARABIC_LETTER_FOLDS` and `ARABIC_LETTER_PATTERN` list the same code points by hand; every class is test-covered, so deriving the regex from the map keys is a follow-up only.
  - Code tests cite ADR-0007 but `docs/adr/` has no `0007-*` file; pre-existing repo-wide (from #120), not introduced here.

## Spec

**Verdict: pass, no blockers.**

- **Strict fold** — all required classes (`أ إ آ ٱ ٲ ٳ→ا`, `ى/ئ→ي`, `ة→ه`, `ؤ→و`) plus the leading `ال` fold; `اليوز`→`ليوز`, `احمد`→`أحمد`, `مصطفي`→`مصطفى` pinned in unit and e2e tests.
- **Applied everywhere search runs** — `rankCatalog` (catalog + sale/purchase item pickers) and `filterParties` (party list + picker). Expenses/activity have no text search (expenses filter by category/window; activity is a capped list); the design records this and a grep confirms it.
- **Typo tolerance only as fallback** — `بطلرية`→`بطارية` (0.833). Strict matches are never displaced: fuzzy runs after every strict tier in the catalog (and only when below the limit), and only replaces an empty strict result in the party list. The 0.8 floor is strict-greater, so `زيت`/`زيوت` (0.75) and the insert/delete relatives `محمد`/`محمود`, `كرسي`/`كراسي` (0.8) stay out.
- **Identity normalizer untouched** — no diff to `normalizeTextKey`; the guard test proves «أحمد» and «احمد» remain two identity keys while search finds both.
- **No pagination / limit / list-rendering changes** — `items.tsx`, `parties.tsx`, `activity.tsx`, `DEFAULT_CATALOG_LIMIT`, and the router are untouched.
- **Documented widening (not creep):** punctuation/separators fold to word breaks (`ليوز-زبون` ≡ `ليوز زبون`) and a sub-2-letter stem is not stripped (`الي` stays `الي`). Both close precision/robustness gaps found in review; neither contradicts the spec.
