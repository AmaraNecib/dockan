# 159 + 160 + 166 — Completion screens, dark-mode inputs, RTL table cells

**Tier:** Standard (UI; no money math changes — the cards only *display* the
figures the server already wrote)
**Base:** `origin/develop` (`0b4ec68`, the same commit this worktree started at)
**Branch:** `feat/159-ui-hygiene`

Three UI-hygiene issues that all touch the same forms/tables, so one lane and
one review.

## Problem

1. **#159** — after a sale, purchase, return or payment the success state is a
   bare `<p>` plus one bordered button. No way to open the document that was
   just saved (the flow navigates back to a fresh form), and the text and
   button do not line up.
2. **#160** — several raw `<input>`s carry `rounded border px-3 py-2` with no
   `border-input` / `bg-background` / focus ring, so on the dark surface they
   are near-invisible. Worst: the payment panel amount/note and the return
   reason.
3. **#166** — `dir="ltr"` on a `<td>` makes `text-align: start` resolve to the
   *left* edge, so a number cell no longer lines up under its right-aligned RTL
   header. Inline `<span dir="ltr">` runs (e.g. `<Amount>`) are correct and
   must be left alone.

## Interfaces

### One shared success card (`apps/web/src/components/ui/success-card.tsx`)

```tsx
interface SuccessCardProps {
  title: ReactNode;              // result line (flow test id rides here)
  detail?: ReactNode;            // secondary line, omitted when there is none
  testId?: string;
  className?: string;
  children: ReactNode;           // the single action row
}
function SuccessCard(props): JSX.Element;      // role="status" root
function SuccessCardSpacer(): JSX.Element;      // flex-1, pushes the trailing action
```

- Tokens only (`border-success/40`, `bg-success/10`, `bg-success`,
  `text-success-foreground`, `border-dashed`). No raw colours.
- `role="status"` stays on the card root so the existing "announce success in a
  status role" unit tests and screen-reader live region keep working.
- The action row is `flex flex-wrap items-center gap-2` in the document's RTL
  direction, so the first action sits on the right (primary) and
  `<SuccessCardSpacer />` pushes "new / again" to the trailing edge.

Callers:

| Flow | test id | title | actions |
| --- | --- | --- | --- |
| sale `sale-saved` | card root | `saleSaved` (number) | عرض الفاتورة (primary, link to `/invoices/$invoiceId`), طباعة (`/invoices/$invoiceId/print`), ␣, بيع جديد |
| purchase `purchase-saved` | card | `purchasesSaved` | عرض الفاتورة, طباعة, ␣, فاتورة جديدة; `LinkProposalPanel` BELOW the card |
| return `returns-done` | card root | `returnsSavedNumber` | عرض الإيصال (voucher route), عرض الفاتورة, ␣, مرتجع آخر |
| payment `pmt-done` | card root | `pmtRecorded` | عرض الفاتورة, ␣, دفعة أخرى |

The saved document id is captured from the mutation result
(`invoiceDetailSchema.id`, `returnDetailSchema.id`) — never looked up by number.
The purchase and sale states grow to hold `remainingAmount` /
`counterpartyName` so the detail line can show the debt the server wrote.

The return/payment cards **replace** their form (the flow's saved state), and
"مرتجع آخر" / "دفعة أخرى" bring the form back. The sale/purchase card already
replaced the whole screen.

### Themed raw inputs (`apps/web/src/components/ui/input.tsx`)

```ts
export const inputClass =
  "rounded border border-input bg-background px-3 py-2 outline-none transition-[color,box-shadow] focus-visible:border-ring focus-visible:ring-[3px] focus-visible:ring-ring/40 disabled:cursor-not-allowed disabled:opacity-50 dark:bg-input/30";
```

Every raw `<input>` that lacked `border-input` / `bg-background` uses
`inputClass` (or `cn(inputClass, "…size/layout…")` for the compact table cells).
The vault components and `App.tsx` are out of scope (parallel lane #167) and
already carry the tokens, so they are untouched. No `<textarea>` or native
`<select>` exists in the app.

### The RTL cell utility (`apps/web/src/index.css`)

```css
.cell-ltr { direction: ltr; unicode-bidi: isolate; text-align: right; }
```

Appended at the end (index.css is shared with lane #167 — additions stay
minimal). Applied where `dir="ltr"` sat on a cell:
`party-detail.tsx` (invoice number ×1, payment invoice number ×1),
`invoice.tsx` (return number), `parties.tsx` (phone), `activity.tsx` (ref),
`print-sheet.tsx` (quantity). Inline `<span dir="ltr">` runs are untouched.

## Risks

- **Form removal changes existing tests.** The return/payment success card
  replaces the form, so `returns-form` / `pmt-form` disappear after a success.
  Error paths keep `savedReturn` / `savedPayment` null, so the form stays for
  every existing error assertion. Verified by running the suites.
- **Router in unit tests.** Sale and purchase now render `<Link>`; their unit
  tests must stub `@tanstack/react-router` (as `invoice.test.tsx` already does).
- **Sweep breadth (#160).** Mechanical class-only edits; low risk, but the diff
  is wide. `cn(inputClass, "px-2 py-1")` keeps the compact table inputs' size
  via tailwind-merge.
- **`cell-ltr` specificity.** Unlayered, so it beats Tailwind's layered
  `text-start`; the print sheet's explicit `text-align: center` on its quantity
  column still wins on specificity, so the printed count stays centred.
