# Dokan (دكان) — Design Context

## Users

Shop owner running a car-accessories business in Algeria. Works at a desk during the day in a well-lit shop environment, often on a shared laptop. Primary tasks: recording purchases and sales, printing invoices, tracking customer/supplier debts, monitoring stock levels, reviewing activity logs. Needs speed, clarity, and low cognitive load — this is a professional tool used all day, not a marketing product.

## Brand Personality

**Fast, practical, trustworthy.**

Dokan should feel like a reliable professional shop tool. Prioritize speed, clarity, confidence, and low cognitive load. Avoid playful, flashy, futuristic, or overly decorative aesthetics. No SaaS landing-page energy — this is a workhorse, not a showpiece.

## Aesthetic Direction

**Modern professional POS / inventory / retail-management software.**

- Efficient desktop workflows
- Information-dense but organized layouts
- Strong hierarchy, fast data entry
- Clear tables and forms, minimal visual noise
- No excessive cards, rounded containers, glassmorphism, large decorative gradients, or unnecessary animations
- Layouts optimized for daily shop operations, not marketing

### Theme

Light mode is the primary/default experience. Support dark mode if it fits the design system, but do not sacrifice the light-mode workflow. No automatic theme switching unless it provides a clear benefit.

### Color

Neutral foundation with one strong brand accent:

- **Deep/medium blue** — primary brand accent (trust, professionalism)
- **Green** — semantic success/positive states only, NOT the main brand color
- **Red** — destructive/error states
- **Amber/yellow** — warnings
- **Neutral grays** — normal UI structure

Tint neutrals toward the brand blue hue for subconscious cohesion. Avoid pure black (#000) and pure white (#fff) — always tint.

### Typography

- Arabic-first, RTL layout
- Tajawal for Arabic text (already in use)
- Clear hierarchy with strong contrast between heading and body sizes
- LTR isolation for: DZD amounts, dates, times, phone numbers, barcodes, invoice numbers, technical error codes
- Monospace or tabular figures for numerical data (amounts, quantities) to aid scanning

### Layout & Space

- 4pt spacing scale with semantic tokens
- Use `gap` over margins for sibling spacing
- Self-adjusting grids for card-style content: `repeat(auto-fit, minmax(280px, 1fr))`
- Container queries for component-level responsiveness
- Varied spacing for hierarchy — tight groupings, generous separations
- Cap body text at ~65-75ch
- Left-aligned text with asymmetric layouts where appropriate

## Design Principles

1. **Speed over decoration** — every pixel should help the owner work faster, not look prettier
2. **Information density done right** — dense but organized; clear hierarchy prevents overwhelm
3. **Trust through consistency** — predictable patterns, no surprises, reliable feedback
4. **Arabic-first, LTR-aware** — RTL is the default; LTR content is properly isolated and styled
5. **Accessible by default** — WCAG 2.2 AA as baseline, not an afterthought

## Accessibility

Follow WCAG 2.2 AA good practices:

- Sufficient contrast ratios
- Visible focus states for keyboard navigation
- Full keyboard accessibility
- Clear, descriptive labels
- Readable text sizes
- Non-color-only status communication (icons + color + text)
- Accessible forms, tables, dialogs, and popovers
- Strong Arabic/RTL support with correct LTR isolation for numbers, dates, codes
