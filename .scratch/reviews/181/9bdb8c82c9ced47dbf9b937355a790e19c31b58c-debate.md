## Round-1 subject (Greptile 4/5)

The ADR's documented escape hatch was wrong: it told callers to separate an identical
entry by changing `ref`, but `ref` is in neither `adjustmentDedupKey` nor
`adjustmentSignatureConditions`, so the workaround was impossible. The closing paragraph
was also wrong: it claimed a stamped request does not match an explicit timestamp, when
`serverStamped` drops the timestamp from the query and matches **any** stored time.

## Fix (code-derived, test-pinned)

- ADR-0011 and design D6 now state the exact rule: a duplicate is refused when *either*
  arm matches; the signature arm compares `(supplierId, direction, amount, reason,
  invoiceId)` plus `occurredAt` **only when the incoming request carries one**; `ref` is in
  neither arm. A distinct entry must change the signature, and a keyed request must *also*
  send a new key (a new key alone is not enough; dropping the key is not enough either).
- The closing paragraph now says a stamped request is time-insensitive and matches an
  explicit row at any stored time; an explicit request matches only its own `occurredAt`;
  the stored key differs only for rows written since v4 (legacy rows are backfilled
  time-inclusive).
- Tests pin each claim: `ref` ignored by the key (golden + keyed forms, unit) and a
  ref-only change refused (store); a server-stamped request refused against an explicit
  row at a different time (store); a fresh key with an unchanged signature refused and
  with a changed signature allowed (store); a changed direction distinct (store).
