## Spec

### 1. Major — `.scratch/implementation/295-design.md` (Risks) contradicts `tests/e2e/client-freshness.spec.ts:133`

The doc still says: *"**The headless e2e never hides a tab.** The reader reports `visible` for the whole run, so the hidden-tab branch of `refetchIntervalInBackground` is not exercised there."* Commit `7998a8d` made the reader a hidden tab: `Object.defineProperty(document, "visibilityState", { configurable: true, get: () => "hidden" })` (`client-freshness.spec.ts:133`). The doc is now false, and false in the direction that understates the ticket: it tells the reader the central claim is unproven when it is proven.

I checked it against the pinned library, not from memory: `bun.lock:470` pins `@tanstack/query-core@5.101.4`. In that version `src/focusManager.ts:71-79` — `#focused` is never set to a boolean at runtime (the only `setFocused` call site takes an optional boolean the built-in setup never passes), so `isFocused()` falls back to the live `globalThis.document?.visibilityState !== "hidden"`. `src/queryObserver.ts` gates the tick on `if (this.options.refetchIntervalInBackground || focusManager.isFocused())`. With the reader forced hidden, `isFocused()` is false, so the tick fires **only** because of the background flag, and the focus path cannot fire. The ablation the commit claims holds.

**Fix.** Rewrite the bullet: the runner never hides a tab, the spec forces the reader hidden itself, and the flag is what carries the tick. Keep the disclosure that the override is the spec's own doing.

## Checked and found sound

- **The guard's identity** against the real seam (`stock-posting.ts:139-160`): the derived inflow cost is `cache.costPrice`, which starts from the same `item.costPrice` the router reads (`router.ts:689`), so `expressUnitCost`'s "equal to the derived cost" rule matches the seam exactly; outflows are recorded costless, so dropping their cost is right; `delta === 0` is forbidden by the contract, so a cost correction can never collide with a manual adjustment (its delta differs).
- **The window's clock.** `created_at` is `localDateTime()` and the cutoff is `localDateTime(now − 10s)` — same fixed-width format, so the SQL `gt` is chronological. `gt` is strict, so the effective window is 9–10s (worth knowing, not worth a fix).
- **The transaction discipline.** `withTransactionImmediate` takes the write lock before the guard's first read; `directSeed` copies the store's own entries, so `tx.listStockMovementsSince` runs on the transaction's connection (`drizzle-store.ts:775`), and WAL is on (`db/connection.ts:79`) so the extra read cannot deadlock.
- **The i18n path.** `STOCK_ADJUSTMENT_DUPLICATE` is UPPER_SNAKE, lives in `resources.ar.translation`, and the router-scan test (`i18n.test.ts`) picks it up automatically; the raw code never reaches the owner.
- **The e2e's isolation.** With `document.visibilityState` forced to `"hidden"`, `focusManager.isFocused()` is false (query-core 5.101.4, verified from the published tarball), the focus path cannot fire, and the tick can only come from `refetchIntervalInBackground`. The `visibleFlips === 0` assertion is true by construction of the override — which is the point.
- **Criterion 4.** No dependency, lockfile, schema or `packages/contracts` change; the store port method is internal.
- **The map wiring.** `tests/e2e-selection.map.json` lists the new spec in both the items and dashboard rules, as its own contract requires.
- **Anti-slop and the SAFETY rule.** Every new type assertion carries a `SAFETY:` comment; no `unknown` parameter, no runtime `typeof`, no `shape` in a symbol name.
- **Round-2 items now genuinely closed:** the 10s window, the store's real edge (`repeatCutoff(now + 11s)` → empty, so widening the window now breaks a test), the two-item `itemId` predicate, the checklist's background flag, `HOT_COUNTER_REFETCH_MS` pinned, the removal / blank-reason / dated-adjustment wire cases, the double blank line at `router.ts:290`, and the #96 binary churn (absent from the final diff).
