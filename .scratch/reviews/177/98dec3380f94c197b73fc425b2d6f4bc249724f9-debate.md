## The owner's decision: one resolver

Greptile rounds 2–4 all came from the same mechanism: the client moved a typed name
onto an existing supplier's row while the server re-resolved the name at save time,
so the account shown and the account written could differ. Round 5 deleted the
mechanism instead of patching it.

- `namedTargets`, the adoption `useEffect`, the focus gates, and every row-moving
  path are deleted.
- A typed name is its own outgoing row, sent as `newSupplierName`; an owner-picked
  row is sent as an explicit `supplierId`. The server is the only resolver.
- The server contract is unchanged.

## Verification critic (after the fix)

Confirmed the "shown ≠ written" hole is shut by three layers: the dialog always names
the typed destination; `confirmExisting` is forwarded only for named rows; the server
refuses any unconfirmed write to an account with history. Every probed path either
writes to an account with no history or to a name the dialog listed.
