fix(scripts): judge the change side, and stop the gate's silent passes (#297)

Eight findings from the debate and test-audit lenses at 6c45f2f. Each is fixed
test-first: the new test is red against the pre-fix gate and green after.

F1 CRITICAL — the gate promised "passes on the change" and never read the
change-side statuses. `gateBaseWorktree` now reads them and reports RED-ON-CHANGE
for a test that fails on the change as well (skipping tests already reported
NOT-ON-PARENT), and `verdictPasses` refuses it.
F2 CRITICAL — the timeout -> RUN-INCOMPLETE wiring was a hand-written string. The
timeout is injectable now (`RED_ON_PARENT_TEST_TIMEOUT_MS`, default 120s), and a
~1s hanging fixture asserts the verdict, the exit code and the no-waiver rule.
F3 MAJOR — `unusedWaiverVerdicts` was only called with an empty expectation. A
stray waiver now fails the gate, both as a unit and end to end.
C1 sev7 — an uncommitted or staged test file was a WARNING with exit 0. It is a
problem now: the run fails, and the `--base HEAD` exclusion is gone.
C2 sev6 — one waiver excused a whole file through `.some(changeNames)`. A waiver
matches per test; the tests it does not name are still judged.
C3 sev5 — skipped files were never named. The report lists each one with its
reason and prints the gated count.
C4 sev4 — the copy manifest was written after the loop, so a half-dead run left
orphans behind. It is written on every copy.
C5 sev4 — a manifest entry reached `rmSync` with no containment check.
`manifestTarget` resolves it and returns null outside the worktree.
